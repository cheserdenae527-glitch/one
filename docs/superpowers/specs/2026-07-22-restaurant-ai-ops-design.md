# 餐饮AI运营助手 —— 产品设计规格书

> 版本：v1.1
> 日期：2026-07-22
> 状态：设计稿（已审阅修订）

---

## 一、产品定位

**一句话：** 让不懂运营的餐饮老板，每天花 5 分钟就能把大众点评/小红书/抖音做好。

**目标用户：** 大陆中小餐饮商家（街边店、夫妻店、小型连锁）
- 年营收 50-300 万，老板就是厨师/店长
- 知道大众点评重要，但没有时间/能力运营
- 想发小红书/抖音，但不会写文案、做图
- 愿意为"省时间"付费，每月 99-199 元能接受

**核心价值主张：** 你不是缺好手艺，是缺一个人帮你把店搬到网上。

## 二、整体架构

产品分为三层：

```
┌─────────────────────────────────────────────────┐
│                运营规划层                         │
│  账号创建 · 昵称/头图/背景 · 周计划 · 月计划     │
│  账号阶段策略 · 创作方向规划                     │
├─────────────────────────────────────────────────┤
│                  执行层                          │
│  ┌────────┬────────┬────────┬────────┐          │
│  │内容创作 │图片生成 │视频生成 │评价管理 │         │
│  └────────┴────────┴────────┴────────┘          │
├─────────────────────────────────────────────────┤
│                 数据底座                         │
│  热门榜单库 · 人设模板库 · 用户链接库 · 商家信息库│
└─────────────────────────────────────────────────┘
```

**右侧栏（所有页面常驻）：**
- 热门内容参考面板（260px 宽）
- 创作方向建议
- 手动粘贴链接入口

**贯穿全流程的合规审查层（详见第十二章）：**
- 所有对外发布内容必须经过合规审查才能"保存/发布"
- 广告法违禁词检测 + AIGC 标识 + 差评回复强制人工审核

## 三、用户注册与进门流程

### Step 1 — 账号注册
- 邮箱/手机号注册 + 登录（Supabase Auth）
- 14 天试用倒计时开始

### Step 2 — 填写店铺信息
**必填：** 店名、地址、电话、菜系、客单价范围、目标客群
**选填：** 各平台链接（大众点评/小红书/抖音）
**品牌视觉素材（选填）：**
- 店铺 Logo
- 门头/店内环境照片
- 特色花纹/设计元素
- 菜品成品图

  → 存入商家信息库，后续图片/视频生成时作为风格参考
  → **如选填素材不足（< 3 张）**，系统后续每月提醒一次补充

### Step 3 — AI 人设选择
- 根据店铺信息，AI 从热门数据库中提取匹配的成功模式
- 展示 2-3 套预设人设供用户选择
- 每套人设含：定位句、语气风格、内容方向示例
- 用户也可选"自定义"，后续随时修改

### Step 4 — 进入 Dashboard
- 自动生成第一周运营建议
- 右侧热门参考栏已就绪
- 引导用户进行第一次内容创作

## 四、运营规划层

### 4.1 账号总览
- 三大平台各一张卡片（大众点评 / 小红书 / 抖音）
- 每张卡片显示：账号昵称、头像、粉丝量（有链接时可展示）、最近更新状态
- 未绑定的平台显示"去创建"引导按钮

### 4.2 账号阶段指引
AI 根据以下数据综合判断阶段，**按最高维度取**：

| 维度 | 新建期 | 成长期 | 成熟期 |
|------|--------|--------|--------|
| 注册天数 | 0-30 天 | 31-90 天 | 91 天+ |
| 平台历史评价量（如有链接） | < 50 条 | 50-500 条 | 500 条+ |
| 平台粉丝量（如有链接） | < 100 | 100-1000 | 1000+ |

**任一维度达到更高级别即升级**，避免错判。
每个阶段对应的策略建议见原设计"新建期/成长期/成熟期"三档。

### 4.3 内容日历（周计划/月计划）
- **视图：** 月历格式展示，有内容的日期显示当天标题
- **内容类型：** 点评笔记、小红书、抖音、评价回复、促销活动等
- **颜色区分：** 不同平台用不同颜色标记
- **交互：** 点击日期展开详细计划，可"一键生成内容"跳转到内容创作模块

  **"一键生成"走模板引擎匹配流程：** 日历上的每次"一键生成"自动调用模板引擎的匹配算法（8.3 四层漏斗），选择最合适的切入角度和体裁，注入 Prompt 生成。用户右侧手动选的参考内容可作为额外输入，但不绕过模板引擎。**所有生成路径统一计入模板反馈权重。**

### 4.4 创作方向建议
- 显示在右侧栏（与热门参考共用侧栏区域）
- 基于当前热门趋势 + 店铺人设，推荐具体内容主题
- 来源：模板引擎分析热榜后得出的趋势结论

## 五、内容创作模块（统一生成路径）

> **关键设计原则：所有内容生成（无论用户通过何种入口触发）统一经过模板引擎匹配 → 合规审查 → 输出终稿，无绕过模板引擎的"外挂"生成路径。**

### 5.1 三门入口
```
┌─────────────────────────────────────────────┐
│  ✍ 文案创作    🎨 图片生成    🎬 视频生成    │
│                                             │
│  粘贴链接，一键复刻                          │
│  [粘贴大众点评/小红书/抖音链接...]            │
│  [一键复刻]                                  │
└─────────────────────────────────────────────┘
```

### 5.2 文案创作流程（统一路径）

所有文案生成遵循同一管道：

```
参考来源（右侧选中/粘贴链接/直接创作）
      ↓
模板引擎匹配（8.3 四层漏斗 → 输出 3 个候选）
      ↓（用户选择哪个候选模板，或直接不经选择就生成）
AI 生成（注入：店铺信息 + 人设 + 参考内容 + 模板结构）
      ↓
合规审查（违禁词检测 + AIGC 标识添加 —— 第十二章）
      ↓
结果呈现 → 用户编辑 → 合规复查 → 保存 / 发布
      ↓
反馈回写模板引擎（8.4），计入权重
```

**无论用户是否主动选择参考来源**，模板引擎的匹配都会执行——用户选的参考内容作为额外 Prompt 输入，不影响模板匹配的执行。日历上的"一键生成"也走完全相同的管道。

生成的每条内容记录中，`templateId` 字段必填，记录本次使用的模板 ID。这样模板引擎的反馈数据（8.4）覆盖所有生成行为，不存在"绕过"的情况。

### 5.3 图片生成流程
1. 选择预设样式模板（菜品展示 / 海报 / 封面 / 环境图 / 菜单图 / 活动图）
2. 每个模板有 2-3 个风格变体（白底精拍风 / 餐桌实拍风 / 手绘插画风）
3. 预设样式需提供示例图供用户预览
4. 选择目标平台 → 自动匹配尺寸和构图比例
5. AI 生成多张候选图供用户选择
6. **素材补充提醒：** 如商家注册时上传的品牌素材少于 3 张，生成时弹出提示"建议补充更多门店照片，让生成效果更贴实际"
7. 保存到素材库，支持批量下载

### 5.4 视频生成流程
**路线 A：复刻参考视频**
1. 用户粘贴抖音/小红书视频链接
2. AI 拆解视频脚本（结构、旁白、镜头、BGM 风格）
3. **拆解结果写入模板引擎**：拆分出的脚本结构作为临时模板入临时表，标记"用户参考来源"
4. **模板引擎去重检测**：如果该脚本结构已被其他商家引用过 N 次（阈值待定），标记"建议修改"
5. AI 根据商家信息改写脚本
6. 合规审查 → 生成视频

**路线 B：从模板创建**
1. 选择视频类型模板
2. 可从运营规划日历的文案直接跳转，自动选择对应类型的脚本模板
3. 模板引擎匹配的脚本 → 商家素材注入 → 合规审查 → 生成视频

## 六、热门内容侧栏

### 6.1 服务端总榜单
- 每日定时采集各平台（大众点评/小红书/抖音）餐饮类公开热门内容
- **风险说明：** 采集范围为全平台公开可见的聚合内容，不涉及用户登录态/私域数据，频率为每日一次。法律风险相对可控但仍存在违反平台 ToS 的可能。**「零反爬风险」的判断仅适用于用户手动粘贴链接，不适用于总榜单自动采集。** 如果后续平台政策收紧，需考虑备选方案（如采购第三方数据服务或完全转向用户贡献模式）。

### 6.2 侧栏交互
- **筛选：** 平台（点评/小红书/抖音）、菜系、城市
- **列表展示：** 每项含封面缩略图、标题、店铺名、点赞数、菜系标签
- **选中参考：** 点击某条内容 → 左侧创作区域会展示该内容详情
- **"参考撰写"：** 参考内容作为额外 Prompt 输入注入统一生成管道

### 6.3 用户手动输入
- 侧栏底部始终有"粘贴参考链接"入口
- 粘贴后 AI 分析：提取标题、点赞数、店铺信息、关键词
- 存入用户自己的链接库，下次打开还在
- 此路径零反爬风险

## 七、评价管理模块

### 7.1 评价概览
- 按评分分级：好评 / 中评 / 差评
- 待回复评价列表

### 7.2 AI 回复（按风险等级分审核强度）

| 评分 | 回复策略 | AI 生成后 | 发布控制 |
|------|---------|----------|---------|
| 4-5 星 | 感谢 + 推荐招牌菜 + 欢迎再来 | 自动生成 | **直接发布**, 支持回退 |
| 3 星 | 感谢建议 + 解释改进 + 邀请再次光临 | 自动生成 | **建议人工审核后发布** |
| 1-2 星 | 诚恳道歉 + 具体改进建议 + 引导私信 | 自动生成 + **AI 声明"此为同行建议，请与商家确认具体方案"** | **强制人工审核，不可自动发布** |

**差评回复的"改进方案"必须由 AI 标注为"建议项"而非"已执行项"**，避免 AI 编造不实承诺。例如：
- ✅ "建议您可以联系店主确认最新的食材来源" → 安全
- ❌ "我们已经更换了供应商" → 禁止（AI 无权代表商家承诺）

### 7.3 评价引导
- 生成"引导好评"话术：打印小票二维码、结账时口播引导

### 7.4 关于"读取评价"的实现路径
- 如果用户绑定了大众点评店铺链接，可通过点评公开页面抓取用户评价内容（类似总榜单的采集方式）
- 如需自动回复到点评平台，则涉及点评开放平台权限——目前大众点评开放平台是否对中小商户开放 API 写权限存在不确定性，MVP 阶段可以先做"AI 生成回复内容后用户在平台手动复制粘贴发布"的流程，后续再评估自动化回写

## 八、模板引擎（核心差异化引擎）

### 8.1 模板数据结构

**切入角度模板：**
```json
{
  "id": "tpl_angle_017",
  "type": "angle",
  "name": "横评对比",
  "desc": "同品类对比多家店，突出自家优势",
  "hook": "问题式",
  "tone": ["专业评测", "本地人视角", "体验派"],
  "structure": ["钩子（问题引发好奇）", "逐店对比", "总结推荐"],
  "cuisines": ["火锅", "烧烤"],
  "platforms": ["大众点评", "小红书"],
  "weight": 0.82,
  "used": 127,
  "source": "热榜分析"
}
```

**体裁模板：** 测评体、故事体、攻略体、合集体、对比体、揭秘体、教程体、话题体

### 8.2 提取流水线
1. **每日定时触发：** 读取当日热门榜单内容，每批 20 篇
2. **LLM 逐篇分析：** 提取切入角度、体裁、结构框架、钩子方式、语气特征、适用菜系
3. **去重与聚类：** 同角度合并，保留表现最好的（点赞数最高）
4. **存入模板库：** 初始权重 = 该内容点赞数 / 同类最高赞（标准化到 0-1）

**覆盖量预估：** 初期 20-30 个切入角度 × 6-8 个体裁 ≈ 200+ 种组合，一个商家每周 3-5 篇，可 3-6 个月不重复

### 8.3 匹配算法（四层漏斗）
1. **第一层：** 菜系 + 平台匹配 → 排除不相关模板
2. **第二层：** 排除近 5 篇用过的角度 → 避免重复
3. **第三层：** 按人设筛选匹配的语气方向
4. **第四层：** 加权随机排序（高权重更可能选中，但保证多样性）

**输出：** 3 个候选（角度和体裁均不同）

**适用范围：** 此匹配算法应用于**所有文案生成路径**，包括：
- 内容创作页面手动生成（5.2）
- 内容日历"一键生成"（4.3）
- 用户粘贴链接后的"一键复刻"（5.1）

不存在绕过模板匹配的独立生成通道。

### 8.4 反馈进化系统

**双重权重体系（分层设计）：**

```
总量权重（影响全平台）
         ↓
+ 单店权重偏移（影响该商家）
         ↓
= 有效权重（用于模板排序）
```

**全局基础权重（全平台共享）：**
| 用户行为 | 权重变化 |
|---------|---------|
| 任意商家保存 | +0.1 |
| 任意商家发布 | +0.3 |
| 任意商家编辑后发布 | +0.2 |
| 任意商家重新生成 | -0.1 |

**单店个性化偏移（仅影响该商家）：**
- 该商家对特定模板的正面行为 → 偏移 +0.15
- 该商家对特定模板的负面行为 → 偏移 -0.15
- 新商家初始偏移为 0，积累 10 次使用记录后生效

**双重权重的好处：**
- 个别挑剔商家不会因为连续 3 次"重新生成"就把一个好模板从全平台干掉（只影响他自己的偏移）
- 新商家不是冷启动：直接继承全局权重，第一天推荐质量就不差
- 长期使用后，每个商家看到的模板排序会逐渐个性化

**淘汰机制（每周扫描，作用于全局权重）：**
- 全局权重 < 0.1 → 删除
- 30 天无任何商家使用 → 标记休眠
- 全局被标记"不推荐"累计 20 次 → 降权至 0.1 观察
- 所有删除保留日志，可恢复

### 8.5 创新机制
- **组合变异：** 每月一次，两个高权重角度合并 → 新角度
- **热点注入：** 平台新热点话题 → 自动生成临时模板
- **编辑模式学习：** 用户多次手动修改模式 → 生成变体
- **节日模板：** 结合季节/节日自动生成
- **视频拆解回流：** 用户粘贴的爆款视频拆解出的脚本结构也进入模板库（独立分类标记），参与去重和多样性检测

### 8.6 同质化对抗策略
1. **人设引擎** — 不同菜系/价位/位置的人设天然不同
2. **强制个性化数据注入** — 每次生成强制加入店铺独有信息
3. **参考内容分散** — 用户选不同参考内容，输出自然不同
4. **人工编辑环节** — 所有生成内容为草稿状态，用户可修改
5. **同质化检测** — 系统内跑相似度检测，雷同时自动调整参数
6. **视频复刻去重** — 同一爆款视频的拆解结构被多个用户引用时，自动推荐修改方向

## 九、合规审查层（新增）

> 所有即将对外发布的内容（文案/图片/视频）必须经过合规审查才能标记为"发布"状态。

### 9.1 广告法违禁词检测
- **检查项：** "最"、"第一"、"国家级"、"唯一"、"极致"等极限词；虚假促销横幅
- **技术实现：** 调用违禁词库（定期更新）对生成内容做全量匹配扫描
- **触发时机：** 用户点击"发布"前
- **处理策略：**
  - 命中违禁词 → 高亮标出，建议替换词
  - 强制拦截：不替换不能发布
- **模板层预防：** 违禁词库同步到 Prompt 模板中，让 AI 生成时尽量规避（但不作为唯一防线，发布前仍需扫描）

### 9.2 AIGC 内容标识
- **遵循法规：** 依据《互联网信息服务深度合成管理规定》，AI 生成内容需做显著标识
- **实现方式：** 
  - 成品文案末尾自动添加"本文由 AI 辅助生成，仅供参考"
  - 图片/视频添加不可见水印（元数据层）
  - 用户可手动删除文案标识（保留选择权，但默认添加）

### 9.3 审核强度分级
| 内容类型 | 审核级别 | 说明 |
|---------|---------|------|
| 好评回复（4-5 星） | 自动 | AI 生成后直接发布 |
| 中评回复（3 星） | 建议人工审核 | 高亮建议人工确认 |
| 差评回复（1-2 星） | **强制人工审核** | 不可自动发布 |
| 店铺简介/套餐文案 | 自动 + 违禁词扫描 | 扫描通过即自动 |
| 小红书/抖音文案 | 自动 + 违禁词扫描 | 扫描通过即自动 |

## 十、数据底座

### 10.1 热门榜单库
- 每日凌晨定时采集公开内容
- **风险声明：** 采集范围为全平台公开可见的聚合内容，不使用用户登录态。仍存在违反平台 ToS 的风险。如平台政策收紧，需储备替代方案（第三方数据 API / 纯用户贡献模式）。
- 平台：大众点评、小红书、抖音
- 分类方式：按菜系 + 城市做一级分类
- 存储信息：标题、正文、点赞数、店铺信息、关键词、图片

### 10.2 人设模板库
- 从平台真实成功案例提炼
- 按菜系、价位、客群聚类
- 每套含：定位句、语气关键词、内容方向示例

### 10.3 用户链接库
- 用户手动粘贴的参考链接
- 按用户隔离存储
- 此路径零反爬风险

### 10.4 商家信息库
- 注册时填写的店铺信息 + 品牌视觉素材
- 所有模块共享的上下文数据
- **素材更新提醒：** 如果商家连续 30 天未上传新素材，系统弹窗提醒"建议更新门店照片，让生成内容更匹配"

## 十二、需要避免的坑

### 评价回复的"AI味"
- 三层次去 AI 味：细节注入 → 人设决定语气 → 结构性随机化
- 不做模板化回复，"感谢您的支持，欢迎下次光临"这种不如不回

### 内容同质化
- 不同商家即使信息雷同，也要通过"多维切入角度"制造差异
- 核心思路：不是"找不同"，而是"造角度"
- 系统要有同质化检测 + 主动切换机制
- **视频复刻单独跟踪**，避免多个商家产出结构雷同的爆款仿制视频

### 平台反爬
- 总榜单：目前全平台公开可见内容采集，仍存在违反 ToS 风险
- 城市级/具体数据：用户手动粘贴链接，零反爬风险
- 评价回复：MVP 阶段先做"AI 生成→用户手动复制发布"流程，不自动化回写到平台

### 合规审查
- 所有发布内容必须通过违禁词扫描
- 差评回复必须人工审核
- AIGC 标识默认添加
- 模板 Prompt 层同时预防（前置过滤），但不替代发布前扫描（后置拦截）

## 附录：大众点评文案体系

大众点评本质上是一个"用户决策平台"，文案目标是：**提高搜索点击 → 提高进店率 → 提高成交 → 提高复购**。分为五大类 Agent：

```
大众点评运营Agent
├── 店铺诊断
│   ├── 简介优化（3秒建立第一印象）
│   ├── 标签优化（场景/人群/特色标签）
│   └── 搜索关键词优化（火锅、生日聚餐等搜索词布局）
├── 商品文案Agent
│   ├── 菜品标题优化（老坛酸汤招牌土鸡 > 招牌鸡）
│   ├── 菜品描述（食材来源+制作方式+口感体验+消费场景）
│   └── 套餐包装（标题+卖点+详情）
├── 内容运营Agent
│   ├── 日常动态发布
│   ├── 新品推广
│   └── 活动策划
├── 评论运营Agent
│   ├── 好评回复
│   ├── 差评处理
│   └── 评论引导
└── 营销Agent
    ├── 节日活动
    ├── 新客活动
    └── 老客召回
```
